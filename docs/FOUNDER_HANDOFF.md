# Founder handoff

## Genuine working scope

The repository provides a canonical TypeScript engine, strict JSON Schema validation, allowlisted typed repairs, policy narrowing, privacy-minimized audits, conservative structural drift reports, four adapter fixtures, CLI, local API, TypeScript SDK, thin Python client, protocol schemas, conformance corpus, tests, benchmark, local demos, and a repeatable Codex/Claude MCP mutation harness.

It also provides a coherent local spine for the intended paid team product: authenticated tenants, shared organization policy, durable schema and audit history, signed audit chains, persistent value-free failure clusters, schema quality scoring, evidence-linked recommended fixes, provider/framework/version compatibility matrices, privacy-thresholded aggregate signatures, drift alerts, signed rulesets, retention and export, plans and quotas, and an operator dashboard. This is more than a validator demo, but it remains a single-machine control plane rather than a public SaaS.

The positioning boundary is explicit: deterministic enforcement, SDKs, CLI, adapters, local audit, and public conformance stay useful offline and open. The compounding managed opportunity is the maintained repair-signature corpus, cross-provider/version conformance evidence, drift intelligence, audit trust, and daily operational workflow. The code establishes those collection and delivery mechanisms; production evidence still has to be earned from real use.

## Explicitly deferred

The managed control-plane behaviors now work locally, including authentication, database history, clustering and recommendations, compatibility summaries, aggregate signatures, signed rulesets, policy, dashboard, metering, quotas, rate limits, alerts, exports, retention, and backup/restore. The offline conformance baseline runs in the release gate and a daily CI workflow, but there is still no deployed service, payment settlement, public TLS ingress, cloud KMS, external alert delivery, distributed coordination, multi-region recovery, production reliability certification, live provider-version probe fleet, or accumulated production compatibility corpus. Adapter coverage is representative, and drift is structural rather than learned from production outcomes. The release suite currently has 67 deterministic TypeScript tests plus the Python client test. A fresh 24-call real-agent run passed its machine verifier; 500-request open-API and 300-request managed concurrency passes also completed without mismatches. This is strong local evidence, not production certification.

## Exact next validation step

Integrate with 5–10 design users who operate multiple providers/frameworks or changing schemas. Record only opt-in event metadata distinguishing ordinary validation, repair rule, rejection reason, and drift category. Review every differentiated event against plain validation/native strict mode. Continue only at three real repair/drift users in seven days; kill/reposition at zero.

## Highest risks

The paid wedge may never be invoked; framework adapters may become a maintenance treadmill; safe-looking coercions may still be contextually wrong; hashes may leak low-entropy facts; and a local server must not be mistaken for production infrastructure.
