# Founder handoff

## Genuine working scope

The repository provides a canonical TypeScript engine, strict JSON Schema validation, allowlisted typed repairs, policy narrowing, privacy-minimized audits, structural drift reports, four adapter fixtures, CLI, local API, TypeScript SDK, thin Python client, protocol schemas, conformance corpus, tests, benchmark, and local demos.

## Explicitly deferred

There is no deployed service, authentication, durable database, remote ruleset distribution, cross-customer intelligence, hosted audit history, dashboard, billing, alerts, rate limits, signed audit ledger, or production reliability claim. Adapter coverage is representative, and drift is structural rather than learned from production outcomes.

## Exact next validation step

Integrate with 5–10 design users who operate multiple providers/frameworks or changing schemas. Record only opt-in event metadata distinguishing ordinary validation, repair rule, rejection reason, and drift category. Review every differentiated event against plain validation/native strict mode. Continue only at three real repair/drift users in seven days; kill/reposition at zero.

## Highest risks

The paid wedge may never be invoked; framework adapters may become a maintenance treadmill; safe-looking coercions may still be contextually wrong; hashes may leak low-entropy facts; and a local server must not be mistaken for production infrastructure.
